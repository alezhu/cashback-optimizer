# Раскладка платежей по картам

Инструмент для разбивки платежей по картам с целью максимизации кэшбека.
Написан на TypeScript (React + Vite).

## Запуск

```bash
npm install
npm run dev
```

Откройте адрес, который выведет Vite (обычно http://localhost:5173).

## Сборка

```bash
npm run build     # tsc -b (проверка типов) + сборка production-бандла
npm run preview   # предпросмотр собранного бандла
npm run typecheck # только проверка типов, без сборки
```

## Хранение данных

Карты, группы, платежи и настройка допустимого превышения автоматически
сохраняются в **IndexedDB** браузера при каждом изменении и загружаются
обратно при следующем открытии страницы — ничего дополнительно нажимать не
нужно. Если IndexedDB недоступен (приватный режим и т.п.), приложение просто
работает без сохранения между сессиями.

## Экспорт / импорт

Кнопки «Экспорт JSON» и «Импорт JSON» в шапке приложения позволяют:
- выгрузить текущие карты, группы и платежи в `.json`-файл (например, чтобы
  перенести на другое устройство или сохранить резервную копию);
- загрузить ранее выгруженный файл — это полностью заменит текущие данные.

## Структура проекта

- `src/types.ts` — все типы данных (формы React-состояния и «чистые» типы
  для расчёта).
- `src/data/seed.ts` — стартовые данные (карты и группы из примера),
  используются только при первом запуске без сохранённых данных.
- `src/utils/idGenerator.ts` — генератор id и синхронизация счётчика после
  загрузки/импорта данных.
- `src/services/normalize.ts` — приведение форм (`number | ''`) к строгим
  числовым типам для расчёта.
- `src/services/calcService.ts` — расчёт комиссии платежа (с учётом
  переопределения, округления, мин/макс комиссии) и суммы к списанию.
- `src/services/allocationService.ts` — эвристика распределения групп/платежей
  по картам и формирования транзакций.
- `src/services/exactAllocationService.ts` — точный решатель (полный перебор
  с отсечением веток), см. раздел «Алгоритмы расчёта» выше.
- `src/services/db.ts` — сохранение/загрузка состояния в IndexedDB (через
  библиотеку `idb`).
- `src/services/exportImport.ts` — экспорт в JSON-файл и разбор импортированного
  файла с базовой валидацией.
- `src/components/cards` — вкладка «Карты».
- `src/components/groups` — вкладка «Группы» (группы и платежи внутри них).
- `src/components/calc` — вкладка «Расчёт» (результаты по картам и транзакциям).
- `src/components/DataToolbar.tsx` — кнопки экспорта/импорта.

## Алгоритмы расчёта

На вкладке «Расчёт» можно выбрать один из двух режимов:

- **Эвристика — быстро** (`src/services/allocationService.ts`). Двухшаговый
  подбор (рюкзак по целым группам + точечное разбиение одной группы под
  оставшийся зазор), близкий к оптимуму, но без гарантии — считает почти
  мгновенно при любом количестве платежей.
- **Полный перебор — максимум кэшбека** (`src/services/exactAllocationService.ts`).
  Перебирает варианты назначения каждого платежа на карту с отсечением
  бесперспективных веток (branch and bound) и берёт лучшую по суммарному
  кэшбеку комбинацию. Перебор ограничен бюджетом узлов — на больших наборах
  платежей может не успеть завершиться честно и вернуть лучшее найденное
  решение с пометкой, что оптимальность не доказана (в интерфейсе это видно
  по бейджу под кнопкой «Рассчитать»).

## Логика комиссии по платежу

Для каждого платежа комиссия считается так:

1. ставка = своя комиссия платежа (`commissionOverride`), если задана, иначе
   комиссия группы (`commission`);
2. `сумма_комиссии = amount * ставка / 100`;
3. подрезается снизу/сверху `minCommission` / `maxCommission` группы (если заданы);
4. если у группы включён флаг `roundCommission` — результат округляется до
   целого рубля (`Math.round`).

Итоговая сумма к списанию по платежу = `amount + сумма_комиссии`.
